إزاي نربط الأجهزة وإحنا بعاد عن بعض؟

الـ IP عندنا بيتغير، وكتير من شركات الإنترنت بتحط الراوتر ورا CGNAT، فـ port forwarding مش حل. الحل: شبكة خاصة افتراضية (Tailscale، الخطة الشخصية المجانية). كل جهاز بياخد اسم ثابت زي siem وtarget حتى لو الـ IP الحقيقي اتغير.

حد الخطة المجانية: لحد 6 مستخدمين وأجهزة شخصية غير محدودة حسب صفحات الأسعار في أغسطس 2026، وكان زمان 3 مستخدمين بس. اتأكد من صفحة الأسعار في الأسبوع الأول. لو عددكم زاد أو الحد اتغير، البدائل المجانية: Headscale (بتستضيفه بنفسك) أو ZeroTier.

مين بيشغّل إيه؟

أقوى كارت (3060 ورامات 16)ai-host: Ollama وخدمة FastAPI. الجهاز الوحيد اللي محتاج النموذج الكبير.
أكتر رامات (16 جيجا فأكتر)siem: جهاز Wazuh الافتراضي (4 vCPU و8 جيجا).
جهاز تالتattacker وtarget (2 جيجا لكل واحد). خفاف ومش بيعطلوا الـ SIEM.
باقي الفريقanalyst من المتصفح، وكل واحد يطوّر على ملفات alert جاهزة ونموذج 3B خفيف.

مش لازم كل واحد يشغّل كل حاجة. الفكرة إننا نوزع الأحمال على الأجهزة ونتشارك الباقي عبر الشبكة.

الخطوات

  1. واحد من الفريق يعمل الحساب وينشئ الشبكة (tailnet) ويدعو الباقي من لوحة الإدارة.
  2. ثبّت Tailscale جوه كل VM وعلى جهاز الـ AI، مش بس على اللابتوب: 
    curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up --hostname=target     # attacker | target | siem | ai-host
  3. حط وسوم (tags) للأجهزة وطبّق قواعد الوصول (ACL) تحت. الأصل ممنوع، وبنفتح بس المسارات اللي في الرسمة.
  4. استخدم الأسماء في كل حاجة: وكلاء Wazuh بيشاوروا على <address>siem</address>، والـ SIEM بينادي http://ai-host:8000، وقائمة الـ allow-list بالأسماء مش بالـ IP.
  5. سيب Ollama على 127.0.0.1. الفريق بيكلم خدمة FastAPI بس على بورت 8000 بتوكن.

تحذيرات مهمة للمشروع

  • متفعّلش Tailscale SSH على target. بيتخطى sshd، فهجمات الـ brute force مش هتظهر في auth.log والـ rules مش هتشتغل.
  • خلّي Suricata على target يسمع على الواجهة tailscale0، لأن ترافيك الهجوم بيوصل منها.
  • الـ attacker يوصل لـ target بس. وما تفتحوش أي بورت من المعمل على الإنترنت العام.
  • جرّب مرة واحدة في بداية الأسبوع الثاني إن قاعدة block_ip فعلًا بتقطع ترافيك الشبكة الخاصة من عنوان الـ attacker.

إزاي نربطهم ببعض؟

الطريقة الأولى (الأسهل والأفضل): Tailscale على الجهازين، نفس خطوات الفريق بالظبط. الأسماء بتشتغل سواء الجهازين في نفس البيت أو في مكانين، ومفيش إعداد راوتر.

الطريقة التانية: الشبكة المحلية. الجهازين على نفس الراوتر (يفضل كابل Ethernet):

  1. في VirtualBox خلّي كارت الشبكة للـ VMs على Bridged Adapter عشان ياخدوا IP من الراوتر.
  2. ثبّت الـ IP من الراوتر (DHCP reservation) أو اكتب الأسماء في ملف /etc/hosts على كل جهاز، علشان ما تتغيرش عليك.
  3. خلّي خدمة FastAPI تسمع على الشبكة (--host 0.0.0.0) بتوكن، وسيب Ollama على 127.0.0.1.
  4. في جدار حماية ويندوز، افتح بورت 8000 للجهاز التاني بس.
هذه الطريقة تعمل داخل البيت فقط. لو هتشتغل من بره البيت أو مع الفريق، استخدم Tailscale.

إزاي نحمي ملف .env؟

  1. قبل أول commit: تأكد إن .env مكتوب في .gitignore، وتحقق بـ: 
    git check-ignore -v .env      # must print the ignoring rule
git status                    # .env must not be listed
  2. الملف المرفوع هو .env.example بس، وفيه قيم وهمية. كل واحد ينسخه: cp .env.example .env.
  3. hook يمنع التسريب قبل الـ commit: 
    pip install pre-commit
pre-commit install            # gitleaks now scans every commit
  4. على GitHub: Settings ثم Code security: اتأكد إن Secret scanning وPush protection شغالين.
  5. لو اتسرّب سر: الأول الغي المفتاح وغيّره (AbuseIPDB، وتوكن Telegram من BotFather، وتوكن الـ FastAPI). بعدين نضّف التاريخ بأداة git filter-repo. حذف الملف في commit جديد مش كفاية، وافترض إن المفتاح اتحرق.
  6. مشاركة الأسرار في الفريق: كل واحد يعمل مفاتيحه المجانية بنفسه (AbuseIPDB وTelegram bot). توكن الـ FastAPI المشترك يتبعت مرة واحدة برسالة خاصة، وغيّره بعد انتهاء المشروع. متبعتوش .env في جروب أو سكرين شوت.
  7. العينات: قبل ما ترفع أي سجلات أو alerts للريبو، امسح الـ IPs الحقيقية وأسماء المستخدمين.

الاتصال بطيء أو متقطع

لو الاتصال المباشر مش ممكن، Tailscale بيعدّي الترافيك على سيرفرات وسيطة (relays) وده أبطأ. الأجهزة المتصلة من نفس الشبكة بتتصل مباشرة. للأحمال التقيلة زي السجلات الكبيرة، اجمعوا الأجهزة اللي بتتكلم كتير مع بعض في نفس المكان لو أمكن.

الـ agent مش بيظهر في Wazuh

اتأكد إن tailscale status بيورّي siem، وإن الـ ACL بتفتح بورتي 1514 و1515 من target لـ siem، وإن العنوان في إعداد الـ agent هو اسم siem مش IP قديم.

النموذج بطيء جدًا

شغّل ollama ps. لو فيه جزء على CPU، انزل لـ llama3.2:3b أو قلّل num_ctx، وأقفل أي نموذج تاني محمّل.

عددنا زاد عن حد الخطة المجانية

استخدم Headscale (سيرفر تحكم بتستضيفه بنفسك) مع نفس عملاء Tailscale، أو ZeroTier. الأسماء والـ ACL بتتنقل بتعديل بسيط.

للاستخدام التعليمي داخل معمل معزول فقط. ما تشغّلوش أي تقنية هجوم على أنظمة مش بتاعتكم.
